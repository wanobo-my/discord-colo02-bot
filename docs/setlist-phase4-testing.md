# フェーズ4：実アップロードの検証手順

dry-run を解除し、実際に Google Drive へ保存する動作を確認します。所要 20〜30 分程度。

---

## 事前に

### フェーズ3との違い

| | フェーズ3 | フェーズ4 |
|---|---|---|
| `SETLIST_MODE` | `dryrun` | **`on`** |
| Drive への書き込み | しない | **する** |
| ✅ リアクション | 付けない | **付ける** |
| スレッドへの返信 | しない | 失敗・対象外があったときのみ |

**実際に Drive にファイルが作られます。** 確認後に削除してください。

### 挙動の要点

- **全添付を処理し終えてから ✅ を付けます。** 1 件でも失敗したら ✅ を付けません
  （付けてしまうと再送しても処理されなくなるため）
- **全件成功したときは ✅ だけで、メッセージは投稿しません。** スレッドが通知で埋まるのを避けるためです
- **失敗・対象外・未分類のときだけ返信します**
- ✅ を外しても**自動では再処理されません**（詳細は下の E を参照）

---

## 手順

### 1. `.env` を書き換える

```
SETLIST_MODE=on
```

`LOCAL_DEV=true` はそのままにしてください。

### 2. ローカル bot を再起動

```bash
cd "/Users/m.yuto/Obsidian Vault/discord-colo02-bot" && npm start
```

起動ログで `📋 曲目リストの回収モード: on` を確認してください。

### 3. 案内メッセージを用意（既にあれば不要）

```bash
cd "/Users/m.yuto/Obsidian Vault/discord-colo02-bot" && npx tsx scripts/post-setlist-anchor.ts "2026.07.30_テストモード" --post
```

## 確認項目

### A. 単一ファイルの保存

案内メッセージに返信して画像を 1 枚送る。

| 観点 | 期待する結果 |
|---|---|
| ログ | `✅ [曲目リスト] 保存しました: 2026-07-30_テストモード_01.png` |
| Discord | 送ったメッセージに ✅ が付く |
| Discord | **余計な返信は投稿されない** |
| Drive | `#記録_曲目リスト/2026/` に想定した名前で保存されている |

### B. 複数ファイルの一括保存

画像を 3 枚まとめて 1 メッセージで送る。

| 観点 | 期待する結果 |
|---|---|
| ログ | 3 件それぞれ「保存しました」が出る |
| Drive | `_02` `_03` `_04` と連番が続く（A で `_01` を使ったため） |
| Discord | ✅ は **3 件すべて完了してから 1 つだけ**付く |

### C. 対象外ファイルの扱い

画像 1 枚と、動画または zip を 1 つ、同じメッセージで送る。

| 観点 | 期待する結果 |
|---|---|
| Drive | 画像だけが保存される |
| Discord | 「対象外のファイルがありマシタ」と返信が来る |
| Discord | 画像の保存は成功しているので ✅ が付く |

### D. 冪等性（同じメッセージの再処理）← **最重要**

A で送ったメッセージを、専用スクリプトで**もう一度処理**させます。
通常の運用では同じメッセージが再処理されないため、意図的に再実行して確認します。

まず対象メッセージの ID を取得してください（メッセージを右クリック →「IDをコピー」。開発者モードが必要です）。

**別のターミナル**で実行します（bot は起動したまま）。

```bash
cd "/Users/m.yuto/Obsidian Vault/discord-colo02-bot" && npx tsx scripts/reprocess-setlist-message.ts "2026.07.30_テストモード" 1531897396706021457
```

> ⚠️ 末尾のメッセージ ID は実際の値に置き換えてください。
> **山括弧などで囲まないこと。** `<` `>` はシェルのリダイレクト記号として解釈され、
> `zsh: parse error` になります。

| 観点 | 期待する結果 |
|---|---|
| ログ | `ℹ️ [曲目リスト] 既に ✅ が付いているためスキップします` |
| Drive | **ファイルが増えない**（ここが冪等性の証明） |

### E. ✅ を外した場合（実装対象外）

**✅ を外しても自動では再処理されません。** リアクション削除を検知する仕組みは、
運用上その場面が想定されないため入れないと判断しました（2026-07-29）。

ただし ✅ が無いメッセージは「未処理」とみなされるため、
D のスクリプトで再処理すれば取り込めます。フェーズ5のバックフィルでも同じ扱いです。

つまり「✅ を外す」は自動再処理のトリガーではなく、
**再処理したいときに手動で実行するための前提条件**という位置づけです。

### F. 未分類への退避（任意）

スレッド名が `YYYY.MM.DD_施設名` 形式でないスレッドで試すと、`_未分類/` に保存され、
その旨がスレッドに返信されます。テスト用スレッドの名前を一時的に変えるなどして確認できます。

## 終わったら

1. **Drive のテストファイルを削除**（`#記録_曲目リスト/2026/` 配下、`_未分類/` を作った場合はそれも）
2. bot を `Ctrl + C` で停止
3. `.env` の `SETLIST_MODE` は `on` のままで構いません（本番反映時も同じ値です）

---

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| `環境変数が未設定のため Drive に接続できません` | `.env` の OAuth 系 4 変数を確認 |
| `invalid_grant` | リフレッシュトークンが失効。`scripts/get-refresh-token.ts` で取り直す |
| `File not found` | `SETLIST_ROOT_FOLDER_ID` が誤っているか、認可アカウントが違う |
| ✅ が付かない | ログに失敗が出ているはずです。1 件でも失敗すると ✅ は付けません |
| 保存はされたが ✅ が付かない | `message.react` の権限不足の可能性。ログを確認してください |
| 何も反応しない | フェーズ3の手順書「うまくいかないとき」を参照 |

## 本番反映について

ローカル検証が済んだら、Koyeb へ反映します。**マージのタイミングは指示があるまで行いません。**

反映時に Koyeb へ登録が必要な環境変数：

```
GOOGLE_OAUTH_CLIENT_ID
GOOGLE_OAUTH_CLIENT_SECRET
GOOGLE_OAUTH_REFRESH_TOKEN
SETLIST_ROOT_FOLDER_ID
SETLIST_MODE=on
```

`LOCAL_DEV` は **Koyeb には設定しないでください**（設定すると cron もコマンドも止まります）。
