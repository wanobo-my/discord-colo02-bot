# フェーズ3：dry-run 検証手順

コンサートスレッドに送られた曲目リストを bot が正しく検知できるかを、
**Drive には一切書き込まずに**確認する手順です。所要 15〜20 分程度。

---

## 事前に知っておくこと

### 何を確認するのか

bot は以下を判定してログに出すだけです。**アップロードも ✅ リアクションも行いません。**

- 返信先が bot の「曲目リスト」案内メッセージか
- コンサートフォーラム配下のスレッドか
- 実施日・法人名・施設名をどこから特定できたか
- 添付が対象の形式・サイズか
- Drive 上のどこに、どんな名前で保存する予定か
- 添付の URL が実際に取得可能か（署名付き URL の失効チェックを含む）

### 二重起動について

Koyeb で本番 bot が動いたままローカルでも起動すると、**同じ bot が 2 つ動きます。**
メンションへのリアクションが 2 回付いたり、定期処理が 2 回走ったりします。

これを防ぐため、**`LOCAL_DEV=true` を付けて起動します。**
このとき以下が無効になります。

- すべての cron（ヘルスチェック / 月初通知 / 月末リマインド / ジョブ巡回 / 16:00 の自動終了処理）
- メンションへのランダム絵文字リアクション
- **スラッシュコマンド・ボタン・モーダルの処理**

曲目リストの検知だけが動く状態になるので、**Koyeb 側は止めなくて構いません。**

> ⚠️ **スラッシュコマンドが無効になる理由**
> 同じ bot が二重に起動していると、Discord は両方に操作を配信します。先に応答した側が勝ち、
> もう一方は `Interaction has already been acknowledged` で失敗します。
> （実測で確認済み。しかも失敗時の応答も失敗するため、ローカル bot がプロセスごと落ちます）
>
> したがって**ローカル起動中は `/concert` などのコマンドを使えません。**
> 検証に必要な「案内メッセージ」は、次項のスクリプトで用意します。

### 案内メッセージの用意について

検証には「**bot が投稿した『曲目リスト』を含むメッセージ**」が必要ですが、
Koyeb の本番 bot はまだ変更前のコードで動いているため、この文面を投稿しません。

そこで `scripts/post-setlist-anchor.ts` を使い、案内メッセージだけを直接投稿します。
このスクリプトは Gateway 接続を張らず REST API のみを使うため本番 bot と競合せず、
シート更新や写真アルバムスレッド作成といった副作用もありません。

---

## 手順

### 1. `.env` に 2 行追加

```
LOCAL_DEV=true
SETLIST_MODE=dryrun
```

> `SETLIST_MODE` は `off`（既定）/ `dryrun` / `on` の 3 値です。
> **Koyeb 側にはまだ設定しないでください。** 本番 bot は `off` のまま（＝従来どおりの挙動）にしておきます。

### 2. ローカルで bot を起動

```bash
cd "/Users/m.yuto/Obsidian Vault/discord-colo02-bot" && npm start
```

起動時に以下が出れば正しく設定できています。

```
🧪 LOCAL_DEV=true: cron / メンション反応 / インタラクション処理を無効化して起動します。
   → ローカル起動中はスラッシュコマンドを使えません (本番botが処理します)。
🧪 [LOCAL_DEV] cron をスキップ: */10 * * * *
   … (cron 5 件すべてスキップされる)
🚀 準備完了！ colo2号#7102 が起動しました
📋 曲目リストの回収モード: dryrun  (off / dryrun / on)
```

### 3. 案内メッセージを投稿する

**別のターミナルを開いて**（bot は起動したまま）、まず投稿内容を確認します。
`--post` を付けない限り**投稿はされません。**

```bash
cd "/Users/m.yuto/Obsidian Vault/discord-colo02-bot" && npx tsx scripts/post-setlist-anchor.ts "2026.07.30_テストモード"
```

投稿先のスレッド名・ID と、投稿されるメッセージ全文が表示されます。
内容に問題がなければ `--post` を付けて実際に投稿します。

```bash
cd "/Users/m.yuto/Obsidian Vault/discord-colo02-bot" && npx tsx scripts/post-setlist-anchor.ts "2026.07.30_テストモード" --post
```

> スレッド名で見つからない場合はスレッドID でも指定できます。
> ID はスレッドを右クリック →「IDをコピー」で取得できます（開発者モードが必要）。

> 💡 既存のコンサートスレッドを使う場合、**変更前に作られたスレッドの案内メッセージには
> 「曲目リスト」の文言が入っていません**。そのメッセージに返信しても検知されないので、
> 必ずこのスクリプトで投稿した新しいメッセージに返信してください。

### 4. 曲目リストの画像を返信で送る

bot が投稿した「**📋 曲目リストの画像はこちらへ**」を含むメッセージに対して、
**返信する形で**画像を添付して送信します。

- スマホ：メッセージを長押し →「返信」→ 画像を添付
- PC：メッセージにカーソルを合わせ →「返信」→ 画像をドラッグ＆ドロップ

### 5. ターミナルのログを確認

以下のような出力が出れば成功です。

```
📋 [曲目リスト][DRY-RUN] 対象を検知しました
   スレッド : 2026.07.28_八事福祉会（八事苑デイサービスセンター）  (ID: 1234567890)
   投稿者   : yourname
   取得元   : ConcertThreads シート
   日付     : 2026.07.28
   法人名   : 八事福祉会
   施設名   : 八事苑デイサービスセンター
   添付     : 1 件
   [IMG_1234.jpg] 2.4 MB / image/jpeg
      保存予定: #記録_曲目リスト/2026/2026.07.28_八事福祉会（八事苑デイサービスセンター）_01.jpg
      MIME    : image/jpeg
      URL確認 : ✅ 取得可能
   ※ DRY-RUN のため、Drive への書き込みと ✅ リアクションは行いません。
```

## 確認してほしいポイント

| # | 観点 | 期待する結果 |
|---|---|---|
| 1 | 取得元 | `ConcertThreads シート` と出るか（スレッド名パースに頼っていないこと） |
| 2 | 法人名・施設名 | 括弧の前後で正しく分かれているか |
| 3 | 保存予定パス | 年フォルダと連番が意図どおりか |
| 4 | URL確認 | `✅` になっているか |
| 5 | 複数枚 | 3 枚まとめて送ると `_01` `_02` `_03` と振られるか |
| 6 | 対象外ファイル | 動画や zip を送ると「⏭️ 対象外」と出て、連番が進まないか |
| 7 | 誤爆しないこと | **返信せずに**画像を貼っても**何も出ない**か |
| 8 | 誤爆しないこと | 別のメッセージ（コンサート情報の本文など）に返信して貼っても**何も出ない**か |
| 9 | 誤爆しないこと | コンサートフォーラム以外のチャンネルで返信＋画像を送っても**何も出ない**か |

**7〜9 が特に重要です。**「反応しないこと」の確認は見落としやすいのですが、
誤爆すると関係ない画像が Drive に混入するため、ここを必ず確かめてください。

---

## 終わったら

1. ターミナルで `Ctrl + C` を押して bot を停止する
2. `.env` の `LOCAL_DEV` と `SETLIST_MODE` は**そのままで構いません**（次のフェーズ4でも使います）
3. テストで投稿した画像や案内メッセージは削除して構いません（Drive には何も書き込まれていません）

---

## うまくいかないとき

| 症状 | 考えられる原因と対処 |
|---|---|
| 何もログが出ない | **返信になっていない**可能性が高いです。画像を貼っただけでは検知しません |
| 何もログが出ない（返信はしている） | 返信先が bot の「曲目リスト」を含むメッセージか確認。本番bot が投稿した従来の案内文には入っていません |
| スラッシュコマンドが効かない | `LOCAL_DEV=true` の仕様です。本番bot 側が処理するので、Discord 上では正常に動いています |
| `⚠️ CONCERT_FORUM_CHANNEL_ID が未設定` | `.env` を確認してください |
| `取得元: スレッド名のパース` になる | シートに行が無いか、日付/施設名が空です。動作としては正常（フォールバックが働いています） |
| `取得元: 特定できず` | スレッド名が `YYYY.MM.DD_施設名` 形式ではありません。`_未分類/` へ退避する動作になります |
| `URL確認: ❌` | Discord の CDN URL が取得できていません。ログの直前に再取得を試みた記録が出ているはずなので、その内容を確認してください |
| リアクションが 2 回付く | `LOCAL_DEV=true` が効いていません。起動時のログを確認してください |

## 参考：オフラインテスト

Discord にも Drive にも接続せず、命名・判定ロジックだけを検証できます。

```bash
npm test
```

スレッド名のパース（括弧あり/なし、表記揺れ、不正な日付）、添付の受け入れ判定
（画像/PDF/動画、サイズ上限、contentType 欠落時の拡張子フォールバック）を網羅しています。
ロジックを変更した際は、まずこれを流してから実機確認に進んでください。
